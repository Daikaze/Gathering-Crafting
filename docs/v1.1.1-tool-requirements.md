# Gathering & Crafting v1.1.1 — Gathering & Tool Proficiency

Compatibility: Foundry VTT 14 / D&D5e 5.3.3. Updates crafting and gathering rules; does **not** alter or regenerate the 224 icon assets.

## Unlimited harvesting

There is **no daily gathering action cap** anymore. The old `database.settings.dailyLimit` and per-character `gathering-crafting.attempts` flags remain in existing worlds for compatibility but are ignored. The old GM reset actions and limited-attempt display are removed. Yield per individual action still depends on each node's `minYield`, `maxYield`, danger mode and roll DC.

## Required tools and tool proficiencies

A character must BOTH carry the proper physical item (quantity >0) AND have full tool proficiency in the D&D5e character sheet's `system.tools.<key>.value`. A tool is not automatically granted by a high skill score. Items can be recognized by common names (English/Bulgarian), dnd5e baseItem aliases, or `flags.gathering-crafting.toolKey` (for custom tools).

Default requirements:

| Action | Physical item | D&D5e proficiency |
|---|---|---|
| Mining ores, crystals | Pickaxe / Miner's Pick | Mason's Tools (`mason`) |
| Collecting plants / herbs | Herbalism Kit | Herbalism Kit (`herb`) |
| Monster harvesting | Skinning Knife | Leatherworker's Tools (`leatherworker`) |
| Blacksmithing recipes | Smith's Tools | Smith's Tools (`smith`) |
| Alchemy recipes | Alchemist's Supplies | Alchemist's Supplies (`alchemist`) |

These are campaign house rules. They are stricter than the standard game rules and are configurable by the GM. In **GM Studio**, an individual gathering node or crafting recipe can override both the required physical tool and its proficiency independently. For unusual magical monster drops, the GM can choose Alchemist's Supplies rather than Skinning Knife.

An unmet requirement locks the action in the UI and is also enforced server-side when the action is attempted from the application.

## Crafting success and failure

Every craft rolls `1d20 + ability modifier + (PB × tool proficiency multiplier) + level bonus + tool item bonus` against the recipe's saved DC:

- Blacksmithing: STR, Alchemy: INT, or the selected tool's ability if overridden.
- Proficiency multiplier: 1 for proficiency, 2 for expertise (half-proficiency doesn't meet the gate).
- PB is read from the D&D5e actor's derived `system.attributes.prof`. This already scales with level.
- Additional level bonus = `floor((character level - 1) / 4)` (0 at levels 1–4, 1 at 5–8, ... 4 at 17–20). This house-rule bonus rewards higher-level crafting independently of PB.
- Tool item bonus = numeric `system.magicalBonus` or `system.bonus` on the carried tool, if present.
- **Standard** mode: normal recipe DC, consumes normal ingredients, gives normal output on success.
- **Inspired** mode: one extra unit of the first ingredient, DC+3, double output on success.
- Failed rolls consume spent ingredients but produce **no crafted item**.
- Batch craft (up to existing UI max 10) rolls once for the batch, all units succeed/fail together. This preserves old UI behavior while removing guaranteed success.

If the system fails after consuming ingredients during a *successful* roll, it attempts to restore consumed inventory. Craft failures are deliberately not refunded.

## Local QA

```shell
node --test tests/tool-rules.test.mjs
node tests/smoke.cjs
node tests/artwork.cjs
```

The GitHub packaging workflow runs these checks before it prepares the v1.1.1 installable ZIP. World settings, recipes, materials, player item flags, existing images and custom GM art are preserved.
